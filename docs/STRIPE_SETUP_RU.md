# Подключение Stripe: страница «Тариф и оплата»

Страница находится в кабинете бизнеса: **Настройки → Тариф и оплата** (`/<бизнес>/settings/billing`).
Оформлять и менять подписку может только владелец бизнеса.

Пока переменные не заданы, страница открывается, тарифы видны, но кнопки выключены.

## Переменные

| Переменная | Что это | Как выглядит |
|---|---|---|
| `STRIPE_SECRET_KEY` | Секретный ключ Stripe. Только на сервере | начинается с `sk_test_` (тест) или `sk_live_` (боевой) |
| `STRIPE_PRICE_START` | Цена тарифа «Старт», 5 €/мес | начинается с `price_` |
| `STRIPE_PRICE_BUSINESS` | Цена тарифа «Бизнес», 10 €/мес | начинается с `price_` |
| `STRIPE_PRICE_PRO` | Цена тарифа «Про», 15 €/мес | начинается с `price_` |
| `STRIPE_WEBHOOK_SECRET` | Секрет вебхука, см. раздел «Вебхук и база» | начинается с `whsec_` |

Ключ и цены должны быть из одного режима: тестовый ключ не видит боевые цены, и наоборот.
Название переменных нельзя начинать с `NEXT_PUBLIC_`: ключ попадёт в браузер.

## Где взять значения

Начните с **тестового режима** (переключатель Test mode / Sandbox в Stripe Dashboard).

1. **Секретный ключ:** Developers → API keys → Secret key → Reveal
   (https://dashboard.stripe.com/test/apikeys).
2. **Цены:** Product catalog → Add product (https://dashboard.stripe.com/test/products).
   Создайте три продукта: Start, Business, Pro. У каждого: Recurring, Monthly, EUR, сумма 5, 10 и 15.
   Откройте продукт и скопируйте Price ID (`price_...`) в блоке Pricing.
3. **Портал клиента:** Settings → Billing → Customer portal
   (https://dashboard.stripe.com/test/settings/billing/portal). Включите отмену подписки с вариантом **Cancel at end of billing period**, смену тарифа
   (добавьте три продукта) и обновление способа оплаты, нажмите **Save**. Без сохранения кнопка
   «Управлять подпиской» покажет ошибку.

Для боевого режима повторите шаги 1–3 с выключенным тестовым режимом: продукты, ключи и настройки портала там отдельные.

## Куда записать

**Локально:** в файл `.env.local` в корне проекта (в git не попадает), затем перезапустите `npm run dev`:

```
STRIPE_SECRET_KEY=sk_test_...
STRIPE_PRICE_START=price_...
STRIPE_PRICE_BUSINESS=price_...
STRIPE_PRICE_PRO=price_...
```

**На хостинге (Vercel):** Project → Settings → Environment Variables, те же четыре переменные. После этого нужен Redeploy.
Для Production — боевые значения, для Preview — тестовые.
Там же должен быть задан `NEXT_PUBLIC_APP_URL`: по нему Stripe возвращает клиента обратно.

## Проверка

Тестовая карта: `4242 4242 4242 4242`, срок — любой будущий, CVC — любой.

1. Настройки → Тариф и оплата → «Выбрать тариф»: должна открыться страница Stripe.
2. После оплаты вы вернётесь на страницу; примерно через минуту тариф будет отмечен как «Ваш тариф».
3. «Управлять подпиской» открывает портал Stripe.
4. «Отменить подписку» с подтверждением: появится дата окончания и кнопка «Возобновить подписку». Подписка работает до конца оплаченного периода, в Stripe у неё виден статус `Active` с пометкой об отмене.

Если что-то не так, причина есть в логах сервера в строках `[billing]`:
`401` — неверный ключ, `resource_missing` — неверный Price ID или смешаны тестовый и боевой режимы.

## Вебхук и база (хранение тарифа)

Этот шаг делает тот, у кого есть доступ к Supabase и хостингу. Оплата работает и без него, через поиск Stripe, но с ним тариф хранится в базе и обновляется сразу.

Порядок важен:

1. **Миграция.** Применить `supabase/migrations/0033_workspace_subscriptions.sql`. Production — только по отдельному согласованию.
   Номера `0028`–`0032` заняты GDPR-ветками, поэтому лучше применять по порядку, после них. Миграция зависит только от `workspaces`, и через SQL Editor её можно применить раньше. Но если применить `0033` через `supabase db push` раньше них, потом для `0028`–`0032` понадобится флаг `--include-all`.
2. **Вебхук в Stripe.** Developers → Webhooks → **Add destination** (или Add endpoint). Адрес: `https://ваш-домен/api/stripe/webhook`. События:
   - `checkout.session.completed`
   - `customer.subscription.updated`
   - `customer.subscription.deleted`
3. **Секрет.** Откройте созданный вебхук, в блоке Signing secret нажмите Reveal и запишите значение `whsec_...` в переменную `STRIPE_WEBHOOK_SECRET`. Затем Redeploy.

Вебхук также использует `SUPABASE_SERVICE_ROLE_KEY`, она уже есть на хостинге. В тестовом и боевом режимах Stripe вебхуки и секреты разные.

**Локально** Stripe не может достучаться до `localhost`, нужен Stripe CLI:

```
stripe listen --forward-to localhost:3000/api/stripe/webhook
```

Команда выведет свой `whsec_...`, его нужно записать в `.env.local`.

**Проверка:** в Stripe на странице вебхука у событий должен быть статус `200`, а в таблице `workspace_subscriptions` появится строка.
Ответы вебхука: `503` — не заданы переменные, `400` — неверный секрет, `500` — ошибка, причина в логах `[billing] webhook:` (например, `42P01` значит, что миграция не применена). Stripe повторяет неудачные события до трёх дней.

## Как это устроено и что пока не сделано

- В `workspace_subscriptions` хранятся только идентификаторы Stripe, тариф и статус. Данных карты, имён и e-mail там нет. Доступ только у сервера; строка удаляется вместе с бизнесом, но **подписка в Stripe при этом не отменяется**.
- Вебхук считает событие только сигналом и каждый раз заново читает подписку из Stripe, поэтому повторы и нарушенный порядок событий безопасны.
- Страница читает подписку сначала из базы, потом через поиск Stripe. Поэтому двойная оплата блокируется, даже если миграция ещё не применена или вебхук опаздывает. Поиск обновляется с задержкой до минуты, и пока вебхук не настроен, в это окно можно оформить вторую подписку.
- **Тариф не ограничивает функции.** Все разделы доступны всем, в том числе без подписки.
- Цены на странице заданы в `src/features/billing/plans.ts`. Списывается сумма из Stripe, поэтому при смене цены меняйте её в обоих местах.
