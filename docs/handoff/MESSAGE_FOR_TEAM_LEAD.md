**3. Что слить и в каком порядке**
Порядок: #18 → #19 → #20 → #21 → #22 → #24 → #26. Для каждого PR, кроме #26:
1. Резервная копия и проверка её восстановления (как раньше: dump → восстановить в изолированную копию).
2. Применить миграцию PR к базе: сначала на копии (повтор, сравнение), затем `supabase db push --dry-run`, затем `supabase db push` — отдельное разрешение на каждую.

Миграции: #18 — 0028, #19 — 0029, #20 — 0030, #21 — 0031, #22 — 0032. #24 своей миграции не имеет (использует 0032 из #22).

**5. Известное ограничение (принято тобой)**
Для обычных сервисов (записи, клиенты, финансы) изменение и запись аудита — два отдельных запроса. Если запись аудита не удалась, изменение остаётся, а ошибка логируется (только код, без персональных данных), не глотается молча. Архив, срок хранения, анонимизация, экспорт и запросы субъектов аудируются в базе в одной транзакции.
